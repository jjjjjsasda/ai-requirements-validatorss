# AI Requirements Validator Agent

ИИ-агент для статической проверки документов с требованиями до начала разработки на соответствие
**ISO/IEC/IEEE 29148:2018 (п. 5.2.5, 5.2.6)** и **IEEE Std 830-1998 (п. 4.3)**. Отчёт — на русском языке.

## Возможности
- Входные форматы: **PDF** (`.pdf`, с текстовым слоем), **Markdown** (`.md`), **Text** (`.txt`).
- Пайплайн из трёх этапов:
  1. **Нарезка** документа на атомарные требования: идентификатор из документа (или «—»), раздел, дословная цитата.
  2. **Проверка каждого требования**: однозначность, полнота, проверяемость, единичность, осуществимость,
     независимость от реализации, прослеживаемость и др.
  3. **Проверка набора**: противоречия, дублирование, пропуски, терминология и единицы, согласованность API, версионность.
- **Контроль доказательств**: каждая цитата от модели ищется в исходном тексте кодом; страница (PDF) или
  строка (MD/TXT) вычисляется автоматически. Требования и замечания с ненайденной цитатой отбрасываются.
- Большие документы делятся на части; при ошибках API (429/503, сеть, битый JSON) выполняются повторы,
  при перегрузке модели — переключение на резервные модели.

## 1. Получение ключа LLM
1. Откройте **Google AI Studio**: <https://aistudio.google.com/apikey>.
2. Нажмите **Create API key** и скопируйте ключ (достаточно бесплатного тарифа).

## 2. Установка и настройка
```bash
git clone <URL_вашего_репозитория>
cd ai-requirements-validator
python -m venv .venv
.venv\Scripts\activate        # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env        # Linux/macOS: cp .env.example .env
```

Откройте `.env` и вставьте ключ:
```env
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.8-flash
GEMINI_FALLBACK_MODELS=gemini-3.7-flash,gemini-3.6-flash,gemini-3.5-flash,gemini-2.5-pro,gemini-3.5-flash-lite,gemini-3.1-flash-lite
```
Файл `.env` в репозиторий не попадает (см. `.gitignore`).

## 3. Запуск одной командой
```bash
python main.py <путь_к_документу> <путь_к_отчёту.md> [--model имя_модели]
```
Примеры:
```bash
python main.py docs/requirements.md reports/validation_report.md
python main.py docs/requirements.pdf reports/validation_report.md
```

## 4. Куда сохраняется отчёт
Отчёт в Markdown записывается по пути из второго аргумента (папка создаётся автоматически).
Структура отчёта: паспорт прогона → таблица нарезки требований → проверка каждого требования →
проверка набора → сводка (число требований, нарушений, критичные дефекты) → итог (можно ли начинать
разработку и что исправить в первую очередь).

## Структура проекта
```
main.py            — CLI: разбор аргументов, обработка ошибок
src/document.py    — чтение PDF/MD/TXT, поиск цитат и их местоположения
src/llm.py         — вызов Gemini, JSON по схеме, повторы, резервные модели
src/agent.py       — этапы пайплайна и промпты
src/report.py      — сборка отчёта в Markdown
```

## Ограничения
- Сканированные PDF без текстового слоя не поддерживаются (нужен OCR).
- Проверка выполняется LLM: формулировки замечаний могут отличаться между прогонами; цитаты и места при этом
  всегда проверяются по документу.
